# Odyssey VTT — хендофф для UI/UX дизайнеров

## 0. Прежде чем начинать

**Пять последних точечных фиксов (зум/пан карты, топбар, тёмная тема) на момент передачи ещё не в `main`** — они сидят в ветке `claude/pensive-gates-n18srp`, поверх уже смёрженного PR #206. Если это всё ещё так на момент, когда вы это читаете — работайте с веткой `claude/pensive-gates-n18srp`, не с `main`, иначе увидите устаревшую светлую тему и баг с зумом. Если фиксы уже замёржены — работайте с `main` как обычно.

Репозиторий: `odyssey-services/Odyssey_VTT` (GitHub). Движок: **Unity 6000.4.0f1, HDRP, UI Toolkit** (UXML/USS/C#, не uGUI/Canvas — это важно, если вы по опыту больше знакомы с Canvas-стеком Unity).

---

## 1. Что такое Odyssey VTT, в двух словах

Виртуальный игровой стол (VTT) для настольных RPG — аналог Owlbear Rodeo/Roll20/Foundry. Карта на весь экран, на неё перетаскиваются токены персонажей, мастер (MainGM) управляет видимостью, боем, инвентарём; игроки видят урезанную версию по ролям.

**Прямые референсы, на которые мы ориентировались при проектировании интерфейса** (не стесняйтесь смотреть их сами):
- **Owlbear Rodeo** (owlbear.rodeo) — главный референс по общей философии интерфейса: карта доминирует на экране, UI-панели — лёгкие оверлеи поверх неё, не делят экран фиксированной сеткой.
- **`github.com/odyssey-services/Odyssey_System`** — наш же более ранний прототип (vanilla JS), источник дизайн-языка вкладок, HP-полосок, skeleton-загрузки.
- **`github.com/odyssey-services/Odyssey_Initiative`** — наш же прототип трекера инициативы (React), источник решения "производный порядок хода" и "автофокус камеры при смене хода".

Полный research-отчёт по Owlbear (с цитатами, ссылками, что подтверждено, а что нет) — просите у PM, он большой и технический, не прикладываю целиком сюда.

## 2. Где искать что в коде

Всё UI — в `Assets/Odyssey/Client/`:

| Что | Где |
|---|---|
| Дизайн-система (цвета/шрифты/базовые классы) | `Assets/Odyssey/Client/UI/OdysseyDesignSystem.uss` |
| Старая тёмная тема dev-shell (до редизайна, частично устарела) | `Assets/Odyssey/Client/UI/AppShell.uss` / `AppShell.uxml` |
| Presenter'ы экранов (C#, логика + построение UXML-дерева в коде) | `Assets/Odyssey/Client/Runtime/*.cs`, `Assets/Odyssey/Client/Runtime/Catalog/*.cs` |
| Тесты (если нужно понять ожидаемое поведение компонента) | `Assets/Odyssey/Client/Tests/EditMode/*.cs`, `Tests/PlayMode/*.cs` |

Презентеры по экранам (ищите по имени класса):
- `BoardScreenPresenter` — сама доска/карта (full-bleed, Owlbear-стиль)
- `GameShellPresenter` — верхний топбар + слой оверлеев поверх доски
- `ContentCatalogPresenter` — каталог контента (предметы/оружие/броня/способности/эффекты/навыки)
- Экран персонажа, инвентаря, боя — ищите по именам файлов в `Runtime/`, структура аналогичная (один presenter на экран + модель)

**Важно для дизайнеров:** UI строится в основном **программно из C#** (`VisualElement`-деревья в коде презентеров), а не только декларативно в `.uxml`-файлах через UI Builder. Если открываете `.uxml` в Unity UI Builder и видите пустую/неполную структуру — это нормально, часть вёрстки собирается в рантайме. Классы CSS (`.ody-*`) — та часть, которую реально удобно трогать визуально.

## 3. Ключевые продуктовые решения, которые уже приняты (не нужно заново это обсуждать)

1. **Карта — full-bleed на весь экран**, все функциональные панели (персонаж/инвентарь/каталог/бой/лог) — выезжающие оверлеи поверх неё, по образцу Owlbear. Не делим экран фиксированной сеткой/сайдбарами.
2. **Тёмная тема со светлым текстом** — это финальное решение (отменяет более раннее решение про светлую "D&D Beyond" тему, которое было в ходу раньше в проекте — если где-то увидите упоминание светлой темы в старых доках/комментариях, оно устарело).
3. **Своё действие — мгновенно, чужое — анимированно.** Когда вы сами двигаете токен/меняете значение — отклик без задержки. Когда это делает другой участник за столом (через сеть) — изменение плавно анимируется, чтобы не выглядело телепортацией.
4. **Единый попап/оверлей-примитив** (`OdyPopover`/`OdySelect`) используется для всего: боковых панелей, модалок подтверждения, выпадающих списков, контекстных меню — не изобретаем отдельный UI-компонент под каждый случай.
5. **Единая конвенция вкладок** — одна активная вкладка выделяется заливкой/рамкой, под-вкладки (например в листе персонажа) — капсульной (pill) формы.

## 4. Известные открытые/спорные места (чтобы не наступать на грабли повторно)

- **Ручной визуальный проход по всему интерфейсу ещё не завершён человеком целиком** — делался точечно по мере находок, не прогонялся системно сценарий "каталог → персонаж → инвентарь → бой". Так что встретить что-то визуально кривое, ещё не пойманное — ожидаемо, не стесняйтесь чинить/переделывать.
- **Масштабирование/панорамирование карты только недавно починили** (баг — сцена не двигалась синхронно при зуме/панорамировании, уже исправлено) — если что-то похожее на рассинхрон объектов при зуме увидите — это может быть недочиненный хвост, сообщите PM.
- **Топбар** — ширины элементов сейчас подобраны вручную под одно конкретное тестовое окно (640×480), это **точно требует вашего глаза** на реальных разрешениях — вероятно придётся переделать на нормальный responsive-подход.
- **Reduced motion** — есть переключатель, отключающий декоративную анимацию (пунктир выделения, shimmer-загрузка, плавная интерполяция чужих действий, автофокус камеры). Если добавляете новую анимацию — подключайте её к этому же переключателю.
- Часть экранов работает в режиме "self-scoped" из-за ограничений backend (например нет полного списка персонажей кампании — только свой персонаж + то, что на сцене) — это не баг верстки, это заранее принятое ограничение backend на этом этапе.

## 5. Как увидеть интерфейс живьём

Откройте проект в Unity (6000.4.0f1), сцена `Assets/Odyssey/Client/Scenes/Bootstrap.unity` (build index 0 — создаёт рантайм и сама загружает AppShell), запустите Play Mode. Не открывайте `AppShell.unity` напрямую — без Bootstrap интерфейс не поднимется. Там же — dev-shell для переключения роли (MainGM/Player) и быстрого запуска тестовой сцены с персонажами/токенами.
