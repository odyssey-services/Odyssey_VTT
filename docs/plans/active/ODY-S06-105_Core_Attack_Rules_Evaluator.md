# ExecPlan — ODY-S06-105 Real `IAttackRulesEvaluator` Implementation

## 1. Purpose
Build the first real, production `IAttackRulesEvaluator` -- `CoreAttackRulesEvaluator` -- computing a genuine damage/range/hit resolution from a weapon's own real `DamageExpression`, the actor's real attributes (`ODY-S06-102`), the target's real armor (`ODY-S06-103`), and the real actor-target distance (`ODY-S06-104`). Resolve the long-open `AttackRandomSample` single-int limitation. Final task of the product-owner-directed block-A data-then-evaluator reordering.

## 2. Scope
`AttackDamageFormulaParser.cs` (new, `Odyssey.Rules.Combat`) -- `ADR-030` §6.2's own `DiceFormulaParser` superset. `CoreAttackRulesEvaluator.cs` (new, `Odyssey.Rules.Combat`) -- the real evaluator. `AttackRandomSample` extended (backward compatible). `AttackEvaluationSnapshot` extended with an optional pre-decoded `ActionWeapon` (backward compatible). `AttackEvaluationService` updated: multi-draw RNG, weapon-decode-and-augment step (the production wiring point). Ten new tests (`TC-ATTACK-117`-`126`).

## 3. Non-goals
`ActivateAbility` (`ODY-S06-106`). Modifying `DiceFormulaParser`/`DiceFormula.cs`. Modifying `SqliteAttackStateReader.cs`/`SceneRepositoryContracts.cs`/`InventoryRepositoryContracts.cs` (read only). Changing `IAttackRulesEvaluator`'s own interface. Correcting `ADR-030`'s own stale internal task-number references. A to-hit mechanic independent of range. Body-part-specific armor selection. Action-cost resource consumption (`CostDeltas` stays empty).

## 4. Architecture
`Odyssey.Rules.Combat` gains two new files, both referencing only `Odyssey.Domain` (confirmed by direct `.asmdef`/`.csproj` read before designing anything -- `Odyssey.Rules` cannot reference `Odyssey.Application`, so it cannot call `TypedDefinitionCodec` itself): `AttackDamageFormulaParser`/`AttackDamageFormula`/`AttackFormulaTerm` (a tokenizer producing `DiceGroup`/`Constant`/`AttributeReference` terms, referencing `DiceFormulaParser`'s own published `MinSides`/`MaxSides`/`MaxDiceGroups`/`MaxDiceCount`/`MaxFormulaLength` constants by direct reference); `CoreAttackRulesEvaluator` (implements `IAttackRulesEvaluator`, pure function over `AttackEvaluationSnapshot`). `Odyssey.Domain.Combat` (`AttackPipelineContracts.cs`) gains: `AttackRandomSample.Values` (an ordered `IReadOnlyList<int>`, `Value` preserved as `Values[0]`); `AttackEvaluationSnapshot.ActionWeapon` (an optional pre-decoded `WeaponDefinition?`, via a new backward-compatible constructor overload). `Odyssey.Application.Combat` (`AttackEvaluationService.cs`) gains a `WithDecodedWeapon` step (calls `TypedDefinitionCodec.DecodeWeapon`, builds an augmented snapshot) run before every `rules.Preview`/`rules.Evaluate` call, and draws up to 4 independent RNG values instead of 1 in `EvaluateAttack`.

## 6. State and data flow
`AttackEvaluationService.PreviewAttack`/`EvaluateAttack` call `AuthorizeAndRead` (unchanged) to get the reader-produced snapshot -> `WithDecodedWeapon` calls `TypedDefinitionCodec.DecodeWeapon(snapshot.ActionMechanics...)`; on success, builds a new `AttackEvaluationSnapshot` (same fields, `ActionWeapon` populated); on failure, returns the original snapshot unchanged (not an error) -> `EvaluateAttack` additionally draws 4 independent `1..100` values from the already-created `IAuthoritativeRandomStream` (`drawIndex` 0-3), builds one `AttackRandomSample` from all of them -> the augmented snapshot (+ random sample, for `Evaluate`) reaches `rules.Preview`/`rules.Evaluate` -> `CoreAttackRulesEvaluator.Resolve`: if `ActionWeapon` is null, throws (fail-closed, a non-weapon action item reaching a real evaluator is a content/wiring inconsistency); otherwise parses `DamageExpression` once, then per target: resolves in-range (via `Topology.Entries`, defaulting true when unresolved), sums `Protection` across every `ArmorAndEffects.Entries` matching that target, evaluates the formula (dice terms consuming `AttackRandomSample.Values` sequentially via a per-target cursor reset to 0, or a deterministic average for `Preview`; `attributeReference` terms resolved against `Actor.AttributeValues`, throwing if unresolved), computes `max(0, formulaValue - protection)`, and emits one `AttackDelta` per in-range target -> aggregate `Range`/`Hit` (miss for the whole resolution if ANY target was out of range) and `Armor` (the first armored target's own aggregate) round out the `ProposedAttackResolution`.

## 7. Error handling
A weapon-decode failure inside `WithDecodedWeapon` is not an error -- it leaves `ActionWeapon` null and the snapshot otherwise unaugmented, since most pre-existing test fixtures' own action items are not weapons at all and never reach `CoreAttackRulesEvaluator`. Inside `CoreAttackRulesEvaluator`: a null `ActionWeapon` throws (this evaluator is meant only for real weapon-driven attacks); an unresolved `attributeReference` term throws (ADR-030 §6.2's own fail-closed mandate, translated into the one failure mechanism available to an interface method that must return a value unconditionally). Missing position/armor data is never an error -- it is treated as "in range"/"no protection" respectively, per this task's own governing product-owner decision and the precedent `ODY-S06-103`/`104` already established for their own data.

## 8. Test strategy
`CoreAttackRulesEvaluatorIntegrationTests.cs` (`Odyssey.Tests.Persistence`): every test a real call through `AttackEvaluationService.PreviewAttack`/`EvaluateAttack` or `AttackApplyService.ResolveAttack`, never a direct unit call to `CoreAttackRulesEvaluator`. A test-only `FixedRandomStreamFactory`/`FixedRandomStream` returns prescribed, known raw values per `drawIndex`, letting every RNG-dependent test assert an EXACT expected damage value (computed independently by hand in the test's own comment) rather than only a plausible range -- distinguishing correct behavior (e.g. two dice terms consuming genuinely different draws) from a subtly wrong implementation (e.g. reusing one draw twice) that a range check alone could not catch. Non-RNG tests use a constant `DamageExpression` (e.g. `"5"`) for fully deterministic, exact-value armor/protection assertions. `RulesScopeTests.cs` (`Odyssey.Tests.Architecture`): a text scan of every file under `Packages/com.odyssey.rules/Runtime` for forbidden RNG-type substrings (carefully excluding `AttackRandomSample` itself from the forbidden list, since it legitimately appears throughout `CoreAttackRulesEvaluator.cs`).
