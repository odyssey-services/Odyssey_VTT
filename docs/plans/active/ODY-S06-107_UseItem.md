## 6. State and data flow
`UseItemService.UseItem(reader, apply, catalog, effects, random, clock, campaign, keyEpochId, request)`: three-branch idempotency check (`apply.GetUsage` -- `CompensatedAt != null` -> permanent failure; `CompensationStartedAt != null` -> resume via `apply.CompensateItemUsage` with an empty list, always report failure; else -> existing success) -> `Authorize` (`reader.CanControlActor` or MainGM) -> `reader.Read(campaign, intent, ...)` (resolves the item via `InventoryItemRef.Kind`, decodes `ItemDefinition` from its own pinned `MechanicsSnapshot`, verifies ownership, rejects `HasCharges`, filters `BuiltInEffectRefs` to `EffectDurationType.Instant` via a real catalog round-trip per ref, decodes each one's own `MechanicsPayloadRef` into a `MechanicsPrimitiveEnvelope`) -> `RequiresDice` across every envelope -> conditional RNG draw (up to 4 values, shared across all envelopes) -> `MechanicsPrimitiveInterpreter.Interpret` once per envelope, resource adjustments and effect-application intentions accumulated -> `apply.RecordItemUsage(...)` (one SQLite transaction: fresh item/inventory/character-resources revision re-checks; `SqliteInventoryRepository.ConsumeItemUnitInTransaction`; every `AttackDelta` via `SqliteAttackApplyRepository.ApplyAttackDelta`; the durable `ItemUsage` row, including a serialized `ConsumedItemUnitJson`) -> on success, sequential `EffectApplicationHelper.ApplyEffect` calls (self-targeted, deterministic sub-`CommandId` per effect index), tracking `createdEffectIds` -> if any fails, `apply.CompensateItemUsage` (durably marks `CompensationStartedAt`/the effect-id list first; removes every created effect; reverses resource deltas; restores the consumed item unit via `SqliteInventoryRepository.RestoreConsumedItemUnitInTransaction`; marks `CompensatedAt`) -> `ItemUsageRecord` returned.

## 7. Error handling
Any state-read failure (item not found, not owned by the actor, `HasCharges` set, a `BuiltInEffectRefs` entry's own catalog lookup/decode failure) surfaces as an honest `Result` failure, never a crash. Authorization failure short-circuits before any RNG draw or transaction. A stale `ExpectedItemRevision`/`ExpectedInventoryRevision`/`ExpectedCharacterResourcesRevision`, re-checked fresh inside `RecordItemUsage`'s own transaction, rejects the whole command before any consumption or delta is applied. A retried `CommandId` short-circuits at the very first step, before authorization or RNG derivation. `ApplyEffect` failures trigger full compensation of all three side-effect categories -- item consumption, resource deltas, created effects -- with the SAME durable `CompensationStartedAt`/resumability discipline `106`'s own third доработка established, built here from the start: a retry after an incomplete compensation attempt resumes it and always reports failure, never success.
