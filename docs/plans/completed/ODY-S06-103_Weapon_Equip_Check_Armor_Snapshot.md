# ExecPlan — ODY-S06-103 Weapon Equip-Status Check + Armor Wiring Into Attack Snapshot

## 1. Purpose
Close two of the three remaining data gaps blocking `ODY-S06-105` (the real `IAttackRulesEvaluator`): the action weapon must now be currently `Equipped`, not merely owned; each target's own currently-equipped armor must reach the attack snapshot as real, decoded `ArmorDefinition` data. Second task of the product-owner-directed block-A reordering (`ODY-S06-102` wired attributes; this task wires equip-status/armor; `ODY-S06-104` will wire position/range; `ODY-S06-105` then builds the full evaluator once, consulting all three).

## 2. Scope
`SqliteAttackStateReader.Read` gains a weapon equip-status gate and an armor-aggregation step. `AttackEvaluationSnapshot.ArmorAndEffects` is retyped from `AttackUnavailableInput` to a new `AttackArmorInput` union (`Odyssey.Domain.Combat`). `IInventoryRepository.ListEquippedEntriesByCharacter` added and implemented in `SqliteInventoryRepository`. Seven existing test files' own attack-action-item fixture helpers updated to keep equipping what they create. Six new tests (`TC-ATTACK-105`-`110`). `SLICE-06_IMPLEMENTATION_BACKLOG.md` row `103` moved to `In Review`.

## 3. Non-goals
The real `IAttackRulesEvaluator`/formula-grammar implementation (`ODY-S06-105`). Which of a target's several equipped armor pieces a real hit consults (also `105`'s job) -- this task passes the complete raw list, aggregation/selection is not decided here. `ActivateAbility` (`ODY-S06-106`). `Topology` (the sibling `AttackUnavailableInput` field, `ODY-S06-104`'s own territory) -- untouched, not reshaped to match armor's new type. Any change to `IAttackRulesEvaluator`'s own interface. Rewriting `EquipmentService`/`ItemEffectLifecycleService` logic -- called/read only. `ADR-030` and earlier ADRs (referenced, not revised).

## 4. Architecture
`Odyssey.Domain.Combat` (`AttackPipelineContracts.cs`) gains `AttackArmorAvailability` (2-value enum), `AttackTargetArmorEntry` (`CharacterId`+`ArmorDefinition` struct), and `AttackArmorInput` (a sealed class with `Unavailable(reason)`/`Available(entries)` static factories) -- a small closed union replacing `AttackUnavailableInput`'s own structurally-data-incapable typing for this one field (proven incapable by the already-existing `TC-ATTACK-025`). `Odyssey.Application.Persistence` (`InventoryRepositoryContracts.cs`) gains `IInventoryRepository.ListEquippedEntriesByCharacter`, implemented in `Odyssey.Persistence.Sqlite` (`SqliteInventoryRepository.cs`) via the same `EquippedEntry`/`ItemInstance`/`ItemStack` join `HasAnyEquippedEntryReferencingBodyPart` already establishes, returning real rows via `UNION ALL` instead of a boolean. `SqliteAttackStateReader.Read` (`Odyssey.Persistence.Sqlite`) gains: (a) a `GetEquippedEntry` call on the action weapon plus an `InventoryId` cross-check, failing with the method's existing generic `Rejected(correlationId)`; (b) a new private `ReadArmor` helper that, per target, lists equipped entries, decodes each via `TypedDefinitionCodec.DecodeArmor` (skipping non-`Armor` content types), and aggregates into `AttackArmorInput`.

## 6. State and data flow
`SqliteAttackStateReader.Read` already loads the action item (`GetItemInstance`) and validates ownership -> a new step calls `GetEquippedEntry(InventoryItemRef.ForInstance(...))` and cross-checks its `InventoryId` against the item's own -> failure here is the same generic `Rejected` every other precondition in this method returns, before any snapshot is built. Separately, after building `targets`, a new `ReadArmor(campaign, intent.TargetIds, correlationId)` call: for each target, `ListEquippedEntriesByCharacter` returns every equipped row owned by that character -> for each row, its own `ItemRef` is resolved back to a real `ItemMechanicsSnapshot` (`GetItemInstance`/`GetItemStack`, by `InventoryItemRefKind`) -> non-`Armor` content types are skipped (not an error) -> `Armor`-typed ones are decoded via `TypedDefinitionCodec.DecodeArmor` into a real `ArmorDefinition`, wrapped in an `AttackTargetArmorEntry` tagged with that target's `CharacterId` -> the aggregate list, empty or not, becomes `AttackArmorInput.Unavailable("...")` or `.Available(entries)` and travels in the snapshot exactly where `AttackUnavailableInput` used to.

## 7. Error handling
Any read/decode failure inside `ReadArmor` (a failed `ListEquippedEntriesByCharacter`, `GetItemInstance`/`GetItemStack`, or `DecodeArmor` call) propagates its own real `Error` up through `Read`'s own `Result<AttackEvaluationState>` -- these are infrastructure-level failures, not a business precondition, so they are NOT converted to the generic `Rejected(correlationId)` (that conversion is reserved for the method's own explicit business-rule checks, per its existing convention). A non-`Armor` equipped item is not an error at all -- it is silently skipped, matching the governing ТЗ's own explicit instruction ("пропускать записи, чей ContentType — не Armor, не считать это ошибкой").

## 8. Test strategy
Real SQLite fixtures throughout (`SqliteAttackStateReaderTests.cs`'s own existing temp-directory setup): `TC-ATTACK-105`/`106` prove the equip-gate's new rejection and its preserved legitimate path via direct `_reader.Read` calls (matching this file's own established convention for precondition-gate tests, e.g. `TC-ATTACK-016`/`017`). `TC-ATTACK-107`-`110` prove armor correctness: no armor -> `Unavailable`; one real armor -> `Available` with field-level verification against the fixture's own real `Protection`/`CoveredBodyPartIds` (via a new `CreateContainedArmorItem`/`EquipArmor` helper building a real `ArmorDefinition` and encoding it with `TypedDefinitionCodec.EncodeArmor`, not a hand-written JSON stand-in); mixed armor + non-armor equipped items -> only the real armor entry; two targets -> each own correct entry, verified by a `Single(entries, targetId)` lookup helper rather than assuming list order. Every pre-existing `ItemFor` fixture across 7 files updated to equip; the one `Move`-dependent test's revision-bump step replaced with an unequip/re-equip cycle. Two direct-constructor call sites updated to compile against the new type/interface member.
