# ExecPlan — ODY-S06-102 Attribute Data in Attack Snapshot

## 1. Purpose
Give `AttackParticipantState` real character-attribute data so `ADR-030` §6.2's `attributeReference` formula term (`1d6+STR`) has something to resolve against once `ODY-S06-105` builds the real `IAttackRulesEvaluator`. Today the snapshot carries only `CharacterId`/`LifecycleStatus`/`ApprovalState`, even though `SqliteAttackStateReader.Read` already loads the full `CharacterRecord` (attributes included). First task of the product-owner-directed block-A reordering: wire missing data first (attributes here, armor `103`, position/range `104`), build the full evaluator once (`105`).

## 2. Scope
`AttackParticipantState` (`Packages/com.odyssey.domain/Runtime/Combat/AttackPipelineContracts.cs`) gains `AttributeValues: IReadOnlyDictionary<AttributeDefinitionId, long>`. `SqliteAttackStateReader.Read`'s private `State(CharacterRecord)` mapping copies `CharacterRecord.Attributes`' own `EffectiveValue` into it, for the actor and every target -- no new database read. The two existing direct-constructor call sites updated. Four new tests. `SLICE-06_IMPLEMENTATION_BACKLOG.md` restructured per its own section 10. `test-catalog.json` updated.

## 3. Non-goals
The formula grammar/parser, the mechanics-primitive interpreter, and the real `IAttackRulesEvaluator` (`ODY-S06-105`). `ActivateAbility` (`ODY-S06-106`). Armor/equipment data (`ODY-S06-103`) and position/range data (`ODY-S06-104`). Any change to `IAttackRulesEvaluator`'s own interface. Fail-closed behavior for a missing/unresolvable attribute reference -- assigned by `ADR-030` §6.2 to the future evaluator/parser task, not this one. `ADR-030` itself (referenced, not revised).

## 4. Architecture
No new type, no new module. `AttackParticipantState` (`Odyssey.Domain.Combat`) is extended with a fourth constructor parameter, defensively copied into an internal `Dictionary<AttributeDefinitionId, long>` and exposed as `IReadOnlyDictionary`. `SqliteAttackStateReader` (`Odyssey.Persistence.Sqlite`) is the only production consumer that constructs one from real data; its private `State` helper folds `CharacterRecord.Attributes` (already loaded for `LifecycleStatus`/`ApprovalState`) into the new field via one pass building a dictionary keyed by `AttributeValue.AttributeDefinitionId`, valued by `AttributeValue.EffectiveValue`. `AttackEvaluationService`/`IAttackStateReader`/`IAttackRulesEvaluator` are untouched -- they already pass the snapshot through opaquely.

## 5. Milestones
M1 -- confirm the exact shape of `CharacterRecord.Attributes`/`AttributeValue`/`AttributeDefinitionId` by direct code read (`CharacterRepositoryContracts.cs`, `DevelopmentEconomy.cs`), and confirm by direct grep that exactly two call sites construct `AttackParticipantState` today. M2 -- extend `AttackParticipantState`'s constructor and property. M3 -- extend `SqliteAttackStateReader.State`. M4 -- update the two existing call sites to compile. M5 -- add `TC-ATTACK-101`-`104` to `SqliteAttackStateReaderTests.cs`, verified with a real `AttackEvaluationService.PreviewAttack`/`EvaluateAttack` call, not an isolated reader test. M6 -- restructure `SLICE-06_IMPLEMENTATION_BACKLOG.md` per its own section 3/10. M7 -- validation (`dotnet build`/`dotnet test` full solution, `verify-format.ps1`/`check-repository-policy.ps1`/`verify-test-structure.ps1`), commit, PR.

## 6. State and data flow
`SqliteAttackStateReader.Read` already calls `_characters.GetCharacter` for the actor and each target, returning a full `CharacterRecord` (including `Attributes: IReadOnlyList<AttributeValue>`) -> the existing private `State(CharacterRecord)` helper, previously reading only `CharacterId`/`LifecycleStatus`/`ApprovalState` off that record, now additionally iterates `record.Attributes`, building a `Dictionary<AttributeDefinitionId, long>` of each entry's own `EffectiveValue` -> this dictionary is passed into `AttackParticipantState`'s constructor, which defensively copies it -> the resulting `AttackParticipantState` (for the actor and each target) travels inside `AttackEvaluationSnapshot` exactly as before, now carrying real attribute data a future evaluator can read.

## 7. Error handling
No new failure mode -- `record.Attributes` is a plain, already-successfully-loaded in-memory collection by the time `State` runs (`GetCharacter` has already returned success), so building the dictionary cannot itself fail. The constructor still rejects a null dictionary argument (defensive, matching this struct's own existing null/invalid-argument convention) and an invalid `CharacterId`, unchanged from before.

## 8. Test strategy
Real SQLite fixtures (`SqliteAttackStateReaderTests.cs`'s own existing temp-directory campaign/character/encounter/item setup, unmodified) plus two new helpers: `GrantAttribute(characterId, name, value)` (real `GrantDevelopmentPoints` + `PurchaseAttributeIncrease`, mirroring `CharacterAbilityInstancesTests.cs`'s own established pattern) and `ServiceRequest(...)` (a real `AttackRequest`). Four tests, all calling through `AttackEvaluationService.PreviewAttack`/`EvaluateAttack` against the real `_reader` (not an isolated `Read` call): actor attribute values appear in the snapshot; target attribute values appear in the snapshot; a character with no purchased attributes yields an empty, non-null dictionary; the RNG-bearing `EvaluateAttack` path also carries the values. A minimal fixed-outcome `IAttackRulesEvaluator` stand-in (`RecordingRules`) is used only to let the real pipeline run end-to-end; it asserts nothing about evaluation logic itself, since that is `ODY-S06-105`'s own job. The two pre-existing direct-constructor call sites are updated and re-verified to still pass.

## 9. Validation and acceptance evidence
`dotnet build`/`dotnet test` full solution green (1013 tests: 1009 pre-existing + 4 new). `verify-format.ps1`/`check-repository-policy.ps1`/`verify-test-structure.ps1` green. `git diff --name-status` against `main` confined to: `AttackPipelineContracts.cs`, `SqliteAttackStateReader.cs`, `AttackEvaluationServiceTests.cs`, `SqliteAttackStateReaderTests.cs`, `test-catalog.json`, `SLICE-06_IMPLEMENTATION_BACKLOG.md`, this task's own contract and ExecPlan -- no touching of `ODY-S06-103`/`104`/`105`/`106`'s not-yet-started territory, `ADR-030`, or `SLICE-05_IMPLEMENTATION_BACKLOG.md`. `IAttackRulesEvaluator`'s own interface text unchanged (direct diff check).

## 10. Recovery and rollback
`AttackParticipantState`'s constructor gains a required fourth parameter -- a source-level breaking change with exactly two known call sites (verified by grep), both updated in this same task/PR; no compiled public API surface outside this repository consumes it. No schema change. Reverting this task's source leaves `ODY-S06-101`/`SLICE-05` completely unaffected -- `AttackParticipantState` simply stops carrying attribute data again, and no later task has yet been built against the new field (this is the first task to add it).
